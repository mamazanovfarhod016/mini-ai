# Стиль эталонного Python-кода (для задач Mini AI)

Эталонные решения (`a` в задачах `tools/make_python_tasks.py`) пишет не ИИ, а шаблоны/скрипт.
Чтобы модель училась ХОРОШЕМУ коду, а не просто рабочему, все эталоны следуют этим правилам.
Их же проверяет `server/codecheck.py` (поле `quality`).

1. **Имена** — `snake_case`, не короче 2 символов. Короткие имена `i`, `j`, `k`, `n`, `x`
   разрешены только внутри `for`/comprehension (счётчики, маленькие индексы).
2. **Докстрока** — первая строка функции: одна строка в кавычках, кратко что делает функция.
3. **Без мусора** — не создавать переменные, которые не используются.
4. **Булевы значения** — никогда `if x == True` / `== False`. Писать `if x:` / `if not x:`,
   а функции с булевым результатом — `return условие`, а не `if условие: return True else: return False`.
5. **Циклы** — по элементам (`for item in items`), а не по индексам (`for i in range(len(items))`),
   если индекс не нужен сам по себе.
6. **Ранний выход** — проверки-охранники (пустой список, деление на 0 и т.п.) в начале функции
   с `return`, а не вложенный `if/else` на всю функцию.
7. **Магические числа** — если число нельзя объяснить из кода, дать ему имя константой.
8. **Размер** — тело функции до 12 строк. Одна функция — одна простая задача.
9. **Типы** — аргументы и возвращаемое значение аннотированы (`def f(x: int) -> int:`).
10. **Исключения** — никаких голых `except:` — указывать тип исключения.

Нарушения 4–10 и часть правил 1–3 проверяет AST-анализатор в `codecheck.py`, остальное —
`ruff check` (наборы правил `E,F,W,N,SIM,B,UP,RET,PL`).
