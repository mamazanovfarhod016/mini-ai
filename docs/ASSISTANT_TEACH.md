# Навык ассистента: обучить нейронку Фархода новыми парами (способ 2)

Этот файл — пошаговая инструкция ДЛЯ АССИСТЕНТА (Хермес/Клод), что делать, когда
Фархход присылает в Telegram новые вопросы/ответы для своей нейронки Mini AI.
Репозиторий: `~/Developer/mini-ai` (GitHub `mamazanovfarhod016/mini-ai`, ПУБЛИЧНЫЙ).

## Когда срабатывает

Фархход пишет что-то вроде: «научи нейронку, что...», «добавь пару: вопрос → ответ»,
присылает текстом или файлом JSON-экспорт из приложения (кнопка «Экспорт пар» в
экране «Научить»).

## Шаги

1. **Принять пары.**
   - Если текстом в чате — распарсить вручную в формат `[{"q": "...", "a": "..."}]`
     (можно несколько вопросов на один ответ через `variants`: `{"variants": ["в1","в2"], "a": "..."}`).
   - Если файлом (JSON) — просто сохранить его как есть.
   - Сохранить во временный файл, например `/tmp/new_pairs.json`.

2. **Проверить на личные/чувствительные данные.** Если пары содержат то, что
   НЕЛЬЗЯ публиковать (см. ниже «Личные данные Фархода») — это всё равно идёт через
   `teach.py`, но **личные пары и личные веса НЕ коммитятся в публичный репозиторий**
   (см. раздел «Личная модель» ниже). Обычные пары (не про самого Фархода лично) —
   коммитятся как обычно.

3. **Запустить дообучение (одна команда):**
   ```bash
   cd ~/Developer/mini-ai
   .venv/bin/python tools/teach.py --pairs /tmp/new_pairs.json --build
   ```
   - Без `--build` — быстрая проверка метрик без пересборки APK (если нужно сначала
     посмотреть, не портится ли старое).
   - По умолчанию 250 шагов (~5 мин на CPU). Если пар много (>20) или ответы не
     выучиваются — можно увеличить `--steps 400` (но смотри время, цель ≤15 мин).
   - Скрипт сам: объединит пары с `data/user_pairs.json` (без дублей), подмешает
     replay (`data/replay_pairs.json`, защита от забывания старого), посчитает
     метрики ДО/ПОСЛЕ на контрольных вопросах + новых парах, сохранит веса,
     поднимет версию в `AndroidManifest.xml`, пересоберёт APK.

4. **Проверить вывод скрипта.**
   - `новые пары, точный ответ: X/N` — должно расти после обучения.
   - `контрольные вопросы не испортились: Y/10` — должно быть ≥ 8/10. Если меньше —
     повторить с меньшим `--lr` (например `--lr 4e-4`) или заново (replay защищает,
     но не идеально).
   - APK: `android/build/MiniAI.apk`, размер обычно < 1 МБ.

5. **Прислать результат Фарходу.**
   - Файл APK как `MEDIA:/home/.../android/build/MiniAI.apk` (путь из вывода).
   - Короткий текст: что выучено, метрики до/после, не испортилось ли старое.

6. **Закоммитить и запушить в ветку `feat/teach`** (или актуальную ветку задачи):
   ```bash
   git add data/user_pairs.json model_transformer.json app/www/model_transformer.js android/AndroidManifest.xml
   git commit -m "teach.py: дообучение N новыми парами (<короткое описание темы>)"
   git push origin <ветка>
   ```
   **НЕ мержить в `main`** без явной просьбы владельца, релиз не создавать.
   **НЕ коммитить** ключи подписи, пароли, личные данные (см. ниже).

## Личная модель (факты о Фарходе) — отдельно от публичной!

Репозиторий **публичный**. Если Фархход просит научить нейронку личным фактам о
себе (учёба, MIT, компания Nexus, клиенты, спорт, соцсети и т.п.) — используется
ОТДЕЛЬНАЯ дорожка, не смешиваясь с публичными данными:

- Пары: `data/personal/farhod_pairs.json` (НЕ в git — в `.gitignore`).
- Веса личной модели: `model_personal/model_transformer.json` и
  `model_personal/app_www/model_transformer.js` (НЕ в git — в `.gitignore`).
- APK с личной моделью собирается ОТДЕЛЬНО, например в
  `android/build-personal/MiniAI-personal.apk`, и отдаётся **только владельцу**
  (не выкладывается в Releases, не пушится).
- Запуск дообучения на личных фактах — тот же `tools/teach.py`, но с явными
  путями, чтобы не трогать публичные веса:
  ```bash
  .venv/bin/python tools/teach.py \
    --pairs data/personal/farhod_pairs.json \
    --model-in model_transformer.json --model-out model_personal/model_transformer.json \
    --steps 300
  # APK с личными весами собирается вручную: подложить model_personal/... в
  # app/www/model_transformer.js на время сборки, собрать, положить APK в
  # android/build-personal/, вернуть публичный app/www/model_transformer.js обратно.
  ```
  (Если у `teach.py` в твоей версии нет `--model-in/--model-out` — делай résumé
  вручную: скопируй `model_transformer.json` в рабочую копию, прогони дообучение
  на personal-парах поверх НЕЁ, не трогая файл в репозитории.)

**НЕЛЬЗЯ добавлять в факты (даже в личную модель):** номера телефонов, Telegram
ID, деньги/долги клиентов METTA, пароли, данные о семье, домашний адрес.

## Пример сообщения от Фархода → что сделать

> «Научи её: вопрос "как зовут твою кошку" → ответ "Мурка"»

1. `/tmp/new_pairs.json`: `[{"q": "как зовут твою кошку", "a": "Мурка"}]`
2. `.venv/bin/python tools/teach.py --pairs /tmp/new_pairs.json --build`
3. Проверить вывод (метрики), прислать APK + текст.
4. `git add -A -- data/user_pairs.json model_transformer.json app/www/model_transformer.js android/AndroidManifest.xml && git commit -m "..." && git push`.

```

qalaysan, salom, rahmat, расскажи шутку, который час
```
Это `CONTROL_Q` в `tools/teach.py` и `tests/test_transformer.py` — если ≥ 8 из 10
совпадают с ответами ДО обучения, всё в порядке.
